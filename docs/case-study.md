# 真实案例：某电力工程企业的多 Agent 落地

> 本文档为脱敏案例，隐去真实客户名、项目名、合同号与金额，保留可复用的架构与量化效果。

---

## 客户背景

一家**电力工程企业**，业务覆盖输变电设备采购、工程招投标、供应链管理。日常高频工作集中在两类：

1. **招投标**：频繁参与电网设备招标，需在有限时间内完成标书编制
2. **物资采购**：针对变压器、电缆、阀门等物料，向多家供应商询价、比价、谈判

这两类工作过去完全依赖人工，是典型的"重复、耗时、且出错代价高"的场景。

---

## 痛点

| 痛点 | 具体表现 |
|------|---------|
| 投标慢 | 一份标书从拿到招标文件到成稿，**3-5 个工作日**，且经常熬夜赶工 |
| 采购低效 | 一次询价要逐个联系供应商、微信/电话来回还价、手工汇总报价 |
| 数据风险 | 标书、报价、客户信息散落在个人电脑和聊天记录里，无审计、难追溯 |

---

## 方案：ACSSA 底座 + 垂直 Skill

客户私有化部署 ACSSA 底座（数据不出内网），并配置两类能力：

```
ACSSA 底座（八模块：记忆/通信/审计/编排/运行时…）
  ├── 投标 Skill   —— 上传招标文件 → 解析 → 生成标书 → 废标检查
  └── 采购⇄销售多 Agent 谈判 —— 自动发现供应商 → 询价 → 谈判 → 成交
```

### 场景一：投标助手

- 上传招标文件，底座自动解析（含 OCR 读图）
- 按评分规则生成标书初稿
- 自动做废标项检查，避免低级失误

### 场景二：采购⇄销售自动谈判

- 采购 Agent 说一句"询价 YJV22 4×70 电缆 100 米"
- 自动发现匹配供应商，群发询价
- 多个销售 Agent 各自报价、自动还盘（有价格底线约束）
- 汇总报价，选定成交后自动生成采购单

全程**没有人工介入**，每一笔谈判、每一次成交都写入哈希链审计日志，可追溯、不可抵赖。

---

## 效果（量化）

| 指标 | 之前 | 之后 |
|------|------|------|
| 标书编制耗时 | 3-5 个工作日 | **2-3 小时**（约 10 倍提升） |
| 采购询价 | 人工逐个联系、手工比价 | 多 Agent 自动询价、谈判、成交 |
| 操作可追溯 | 无审计、口头/聊天记录 | 哈希链审计日志，全程留痕 |

---

## 为什么这套方案能在真实生产跑起来

1. **数据主权**：私有化部署，标书、报价、客户数据不经过任何第三方 SaaS
2. **生产级运行时**：Skill 子进程隔离 + cgroups 资源限制 + 崩溃自动重启，能扛真实业务
3. **安全审计**：哈希链日志 + Ed25519 签名，企业敢让 Agent 自动成交的前提
4. **多 Agent 协作**：采购⇄销售是"操作系统"级能力，不是单 Agent 业务

---

## 可复用的启示

- **先跑垂直场景，再谈通用能力**：投标、采购是电力行业的刚需高频场景，价值直接可见
- **数据主权是企业上 AI 的第一道坎**：先解决"数据敢不敢交出去"，再谈"能力够不够强"
- **审计是放权的前提**：企业敢让 Agent 自动成交，是因为每一步都可追溯、不可抵赖
